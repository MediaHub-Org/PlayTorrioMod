# Project Roadmap — PlayTorrioV3

This document lists the **outstanding** work for PlayTorrioV3. Completed work is
consolidated into `CHANGELOG.md`.

## Known issues

Both issues found in the 2026-08-24 desktop-build QA pass are resolved (see CHANGELOG):
TopBar's contrast against dark page content, and Artist/Album/Playlist detail views
being a centered popup instead of a real screen.

**Implemented, awaiting manual confirmation — "Unknown error" dialog after closing
the Windows app** (see CHANGELOG). `WindowService` now calls `setPreventClose(true)`
on init and runs a real shutdown sequence in a new `onWindowClose` handler
(`PlaybackCoordinator.stopActive()`, `LocalStreamProxy.instance.stop()`,
`TorrentStreamService().stop()`, then `windowManager.destroy()`) instead of letting
the OS kill the process while the proxy's HTTP server is still bound. Verified via
`flutter analyze`/`flutter test`/a Windows release build, but actually clicking the
close button and confirming no dialog appears needs a human — no agent in this loop
can interact with a live window.

**Open — mobile section chips overlap the page search icon at narrow widths.**
Confirmed via testing 2026-08-26. Each catalog/section page (`anime_page.dart`,
`manga_page.dart`, `music_page.dart`, `audiobooks_page.dart`, `type_catalog_page.dart`,
`genres_page.dart`) floats its own `PageSearchButton` (and often a `FilterDropdown`)
as a `Positioned(top: 16, right: 16, ...)` overlay independent of `SectionTopBar`'s
horizontally-scrolling chip row above it — neither reserves clearance against the
other's actual rendered width, so on phone-width screens the chip strip's trailing
label and the floating search icon collide. Needs an investigation pass across the
~6 pages using this pattern (not a single-file fix) — see #5 below, same root cause
family as the transition-consistency gap: per-page pattern reuse without a shared
component enforcing the contract.

## Upcoming (priority order)

| # | Task                                                         | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|---|--------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | **QA pass on all 5 platforms** (mobile, tablet, desktop, TV) | Verify no regressions; TV in particular needs a dedicated D-pad/remote-input pass — reported as needing improvement generally. |
| 2 | **Unified hub + submenu navigation component**              | Navigation is split across two disconnected bars: the global `TopBar` (Watch/Listen/Read hub switcher) and the per-hub `SectionTopBar` (horizontal section chips), with each hub re-declaring its own sections in `HubController.currentSections`. Consolidate into a single menu/submenu component — one element where the hub is the top level and its sections are the submenu — so "Watch › Movies", "Listen › Music", "Read › Manga" read as one navigable unit instead of two separate bars. |
| 3 | **Books section is search-only, no browse view**            | Investigated 2026-08-27 as a follow-up to the back-button audit: Radio/Podcasts having no back button turned out to be by design (they're `_activeTab` peer-tab switches, same model as Movies/Series/Anime's section chips, not pushed routes — no fix needed there, ruled 2026-08-27). Books (`lib/pages/read/books_page.dart`) is a separate, real gap though: it's a `TextField` + search results only, no catalog/browse grid like every other Read-hub section (Manga, Comics, Audiobooks) has. `BooksService` (`lib/services/books/books_service.dart`) currently only exposes `search(query)` against libgen.li's `req=` query endpoint — no browse/popular/recent listing method exists yet. Before building a browse UI, needs the same kind of source check the Comics item below already went through: confirm libgen.li actually has a browsable listing endpoint (not just search) before committing to this. |
| 4 | **Consistent page-enter transition**                        | Reported after testing 2026-08-26: page transitions feel inconsistent app-wide. Two custom transitions exist (`LiquidRevealRoute` — 750ms circular reveal expanding from the tap point, `CinematicSlideRoute` — the Watch Screen's slide+fade) but only 30 of the roughly 64 `Navigator.push` call sites across the app use either one — the rest fall through to Flutter's bare default (`MaterialPageRoute` or an unwrapped push), a plain platform slide/fade unrelated to the app's own transition language. Needs an audit of every push site and a decision on which of the two existing transitions (or one new shared default) each page family should use, then applying it consistently instead of per-page/per-author choice. |
| 5 | **Nest Genres inside Movies and Music**                     | Genres is a top-level section chip in both the Watch hub (`Genres`) and the Listen hub (`Genres`). It's really a sub-view of content, not a peer of Movies/Series/Music. Fold it into the Movies/Series catalog and the Music catalog as a nested browse/filter view (mirroring how the decade filter already lives inside the catalogs) rather than a separate top-level section. Narrower in scope than #6 below — this only relocates the Genres chip; #6 reconsiders the catalogs themselves. |
| 6 | **Unify Movies/Series/Anime into one filterable, searchable catalog** | Suggested 2026-08-26, Stremio-style: today Movies, Series, and Anime are three separate top-level sections (`type_catalog_page.dart` × 2, `anime_page.dart`), each with its own decade/genre filter UI built independently. Stremio instead treats them as one discovery surface with tag-based filter + search — type, genre, year, etc. all combinable tags over a single catalog — rather than three parallel, independently-filtered catalogs. Bigger than #5: that item relocates Genres into the existing catalogs; this one replaces the catalogs themselves with a single unified view, so it needs its own design pass on what a mixed-content-type card grid looks like, and whether Anime — which already carries anime-specific metadata Movies/Series don't have — loses anything by joining the same view. |
| 7 | **Like/favorite from the bottom play bar**                  | The `UniversalPlayBar` (shown across all hubs) has cover, title, artist, play/pause, and close — but no like button. Music already has `MusicLibraryService.toggleLikeTrack` and the expanded player shows a heart; the bar should expose the same toggle so a track can be saved without opening the full player. Needs the bar to know the current track's like state (music only — video/audiobook have no like concept). |
| 8 | **Download button on detail/player pages**                  | Suggested 2026-08-26. The download-manager infrastructure already exists (`DownloadService.instance`, the 5-provider Debrid engine, Collection page's Downloads tab — merged from upstream, see CHANGELOG) but nothing in the UI currently starts a download except indirectly, by opening playback and going through the Debrid-resolve flow. Add an explicit download affordance on movie/series/anime detail pages (and the player itself) that calls `DownloadService.instance.startDownload(...)` directly, so a user can queue a download without first opening playback. |
| 9 | **Cast & direction with images**                            | Movies/Series detail pages already show cast and direction with photos (TMDB-enriched when the addon only supplies names — see CHANGELOG). The gap is coverage: anime, manga, and audiobooks have no cast/direction at all, and enrichment only runs for movies/series. Extend the same photo-credit treatment to the other content types where the source data exposes it. |
| 10 | **Read hub: Comics data source**                           | Looked at porting `ayman708-UX/PlayTorrioV2`'s comics feature (`comics_service.dart`, `readcomicsonline_scraper.dart`, `comic_page_extractor.dart`, browse/details/reader screens — same Dart/Flutter stack, would've been directly adaptable) but **both sources it depends on are dead**: `rcostation.xyz` doesn't resolve (DNS gone), and the fallback `readcomicsonline.ru` returns HTTP 403 on every endpoint even with the exact matching User-Agent (looks like Cloudflare/bot-protection blocking plain HTTP requests, which would block the app's `http` client identically) — verified directly via `curl` on 2026-08-24 and re-verified 2026-08-25, no change. Porting as-is would ship a Comics section that just errors out. Holding until a working source is found — either a fixed/alternate scrape target, or a Stremio-style addon (comics addons exist in that ecosystem, matching how Movies/Series/Manga already work here) instead of raw HTML scraping a single site that can vanish. `ComicsPage` (`lib/pages/catalog/comics_page.dart`) stays a placeholder until then. V2 has no other comics source and no podcast feature at all, so neither could be cross-checked against a second port target. |
| 11 | **Filters for Music/Radio/Audiobooks**                     | Movies/Series got a decade filter + sort dropdown, and Anime got a genre filter (see CHANGELOG) — both reusing the new shared `FilterDropdown` widget. Music/Radio/Audiobooks don't have equivalent data yet: `MusicTrack` has no genre field, and neither the Radio nor Audiobooks pages have any genre/category concept today. Needs real genre/category data sourced per content type before a filter can be built there — not a UI gap, a data gap. |
| 12 | **Cloud sync for the JSON backup**                         | Local export/import shipped (see CHANGELOG) as a flat, versioned JSON envelope specifically so this is a transport change, not a rewrite — wire it up to a cloud backend (own server, or a drop-in like a user's own cloud storage) instead of only writing to a local file. |

> **Mobile hub switching via drawer** was dropped: the leftover bottom nav bar it referred to is already gone, and the global `TopBar` (3 fixed hub tabs) + `SectionTopBar` (horizontally-scrolling section chips) already cover every screen width, including mobile — a drawer would duplicate that, not fix a gap.
>
> **IPTV multi-view** shipped (see CHANGELOG) as an original grid feature, not a port of `interneto/tv-multiview` (a pure JS/PWA project, not pullable as a Flutter dependency). Scoped to channels with an already-cached stream, not fresh scans — see the CHANGELOG entry for why.
>
> **`interneto/tv-multiview`'s channel data** (`json-tv/tv-channels.json` -- 96 channels with direct m3u8 URLs, name/logo/category/country) was evaluated as a source for more IPTV channels. Declined: mostly minor national/public broadcasters (34 news, 23 general), the data has no stated license (from `Alplox/json-tv`, marked "(No license)" in their own NOTICE.md), and `HardcodedChannel` has no direct-stream-URL field -- these channels already have a working URL, so bolting them into the existing name+keyword portal-scan model would mean scanning portals for niche broadcasters unlikely to be in that catalog. Using it properly needs a second, direct-play path bypassing the scan entirely -- a real new subsystem, not proportionate to what ~88 working channels (mostly minor) add.

## Architecture: consistency, SOLID, modularity

Cross-cutting cleanup requested — applied consistently rather than as one-off patches. All identified instances are resolved (see CHANGELOG):

- **Duplicated widgets with independently-drifting behavior**: `IptvSliderSection`/`MovieSliderSection` scroll-arrow logic, `IptvChannelCard`/`MovieCard` hover-press animation, `IptvHeroCarousel`/the anime hero carousel's PageController+Timer auto-rotate logic, and `MediaHub`/`BooksHub`'s scaffold shell are all done. `MusicHub`/`music_page.dart` stays a deliberately separate third shape (ambient background, keyboard listener, queue/lyrics drawer overlays) rather than being forced into the same abstraction.
- **Playback progress/state syncing to `PlaybackCoordinator`**: evaluated formalizing this into the `activate()` contract. Music and audiobook drive it from their own custom controllers' internal state; video and IPTV share a duplicated 2-line fragment (`setProgress`+`setPlaying` off a `VideoPlayerController`'s `value`) inside otherwise-unrelated listeners. Forcing all four into one contract would mean an adapter per controller type to paper over genuinely different underlying APIs — real design cost to save two lines, with no current bug from the gap. Left as-is; revisit if a fifth playback type actually forgets the sync.
