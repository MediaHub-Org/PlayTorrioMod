| 5 | **"Search" appears as its own chip in the Listen hub's section bar**                        | `HubController.currentSections` for `AppHub.music` (`lib/utils/hub_controller.dart`) lists `Music, Search, Genres, Radio, Audiobooks, Library` — `Search` sits among content categories even though it's a utility action, not a section, and every other hub instead exposes search via the small `PageSearchButton` icon on the page itself. Reported as "a bit strange but also makes sense" — worth a design decision on whether to drop the Search chip in favor of the same `PageSearchButton` pattern Watch/Read use, for consistency.                                                                                                                                                                                               |

## Architecture: consistency, SOLID, modularity

Cross-cutting cleanup requested — apply consistently rather than as one-off patches. Concrete instances already identified in review (not exhaustive):

- **Three parallel hub-scaffold implementations.** `media_hub.dart` and `books_hub.dart` hand-duplicate the identical `Scaffold > Column[SectionTopBar(), Expanded(_buildSection(...))]` shell; `music_hub.dart` opts out entirely and delegates to `music_page.dart`, which reimplements a third variant with its own extra layers. Extract a shared `SectionedHubScaffold` all three hubs build on.
- **Duplicated widgets with independently-drifting behavior**: `IptvChannelCard` vs `MovieCard` (hover/press animation), `IptvSliderSection` vs `MovieSliderSection` (scroll-arrow logic), `IptvHeroCarousel` vs the anime hero carousel (itself already a known copy of the old home page's carousel — a third copy now exists). Each pair should share one implementation instead of three independently-maintained forks of the same interaction logic.
- **`CollectionPage` reimplements the `LibraryTabs` widget** sitting right next to it in the same PR, instead of using it like `BooksLibraryPage` does.
- **Four near-identical ~150-line modals** in `music_page.dart` (`_MusicArtistDetailModal`, `_MusicAlbumDetailModal`, `_MusicCuratedPlaylistDetailModal`, `_MusicUserPlaylistDetailModal`) share the same shell (header + divider + track list) and differ only in header content — collapse into one parameterized `_MusicDetailModal`.
- **Playback progress/state syncing to `PlaybackCoordinator`** was added ad hoc per call site (music got full sync; video/audiobook/IPTV needed the same boilerplate added separately, see CHANGELOG) instead of being a required part of the `activate()` contract — worth formalizing so the next playback type doesn't repeat the gap.
